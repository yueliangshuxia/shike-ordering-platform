# 食刻点餐 · 前端 Demo

纯静态演示页，**双击 `index.html` 就能打开**，不需要起服务器、不需要联网。

这是给你确认设计用的。定下来之后再照它做真正的 Vue + Spring Boot 项目。

## 设计系统

方向是 **骨白纸 / 松墨绿 / 朱砂**，刻意避开了 AI 生成页面常见的奶油底+衬线+陶土色那套。

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#F2F1EC` | 页面底，偏冷灰不是奶油色 |
| `--ink` | `#1B2621` | 正文墨色，带一点绿不是纯黑 |
| `--pine` | `#1E4034` | 页头、页脚、分类栏等结构色 |
| `--cinnabar` | `#C4321F` | **只用于价格和主操作**，是功能色不是装饰色 |
| `--gold` | `#C08A2E` | 评分星级 |
| `--jade` | `#3E7A5E` | 成功态、素食标记 |

**字体**：标题用思源宋体（`Noto Serif SC`），界面用思源黑体（`Noto Sans SC`）。
两个字体在 Windows 上通常是 `NotoSerifSC-VF.ttf` / `NotoSansSC-VF.ttf`，
装不到会回落到宋体和微软雅黑。**没有引用任何外部字体，不依赖 Google Fonts。**

**记忆点**：点单栏做成「点心单」——左右两条竖朱线、条目间虚线、
数量装在方框里、合计用双线压底、右上角盖一枚朱砂圆章写着桌号。

**动效**：只有一处 —— 加购时印章盖一下。其余地方不做滚动淡入、不给每个卡片加 hover 动画。

## 素材来源

| 类型 | 来源 | 说明 |
|---|---|---|
| 菜品照片 | [Pexels](https://www.pexels.com) | 16 张，已下载到 `assets/img/dishes/`。多出来的 7 张在 `assets/img/unused/`，见下 |
| 插画 | [unDraw](https://undraw.co) | 20 张 SVG，**已重新配色**以匹配本站色板 |
| 图标 | [Iconify](https://iconify.design)（mdi 集合） | 48 个，已本地化为 JS，不走网络 |
| 图表 | [ECharts 5.5](https://echarts.apache.org) | 已下载到 `assets/vendor/` |

**全部素材都在本地**，断网、换台电脑、答辩现场没 WiFi，都不影响展示。

### 需要注意的授权问题

- **unDraw** 的授权允许免费商用和修改，但**禁止用于 AI 训练、禁止整包再分发**。
  论文里引用插图建议在图注或致谢中标注来源。
- **Pexels** 免费商用、无需署名，但**不允许把未修改的原图直接转售**。
- **20 道菜现在都有实拍图**。最后 4 道（艇仔粥、杨枝甘露、冻柠茶、菊花茶）
  是 2026-10-22 由项目作者自己补的，文件名是英文菜名而不是 `pexels-<id>`，
  来源未标注 —— 论文里标注素材时按「作者提供」写。
- 占位图机制保留着：没有 `img` 字段的菜，前端会按菜名生成虚线块。
  以后加新菜忘了配图，一眼就能看出来。要补图，把文件放进 `assets/img/dishes/`，
  再在 `data.js` 里填上该菜的 `img` 字段即可。
- `assets/img/unused/` 里有 7 张**当前菜单用不上**的照片（5 张烧烤、1 张火锅，
  外加 1 张下载时混进来的非食物照片）。2026-10-17 把业态收敛成
  港式茶餐厅之后，烧烤和火锅被去掉了。没有删是因为
  **Pexels 的搜索页在这台机器上返回 403，搜不到新的图**，删了就找不回来。
  详见该目录下的 README。

## 目录结构

```
demo/
├─ *.html                     11 个页面
└─ assets/
   ├─ css/style.css           设计系统，全部样式都在这一个文件
   ├─ js/
   │  ├─ data.js              菜品 / 订单 / 经营数据的假数据
   │  ├─ recommend.js         AHP + TOPSIS 算法实现 ★
   │  ├─ app.js               购物车、点单栏、通用渲染
   │  └─ layout.js            页头页脚模板
   ├─ icons/bundle.js         Iconify 图标数据（本地）
   ├─ illustrations/          unDraw 插画（已改色）
   ├─ img/dishes/             Pexels 照片
   └─ vendor/                 iconify-icon.min.js、echarts.min.js
```

> 页头页脚是用 JS 注入的（`layout.js`），不是复制了 11 份。
> 因为正式版这两个本来就会做成 Vue 组件，现在没必要重复写。

## 脚本（在项目根目录运行）

```bash
# 给某个页面截图，用来检查渲染效果
python tools/shot.py index.html --w 1440 --h 2000
python tools/shot.py "cart.html?demo=1" --w 1440 --h 1200

# 页面里加了新图标之后，重新生成本地图标包

# 重新给插画配色（改了调色板之后跑）

# 把 Pexels 照片拼成一张校对图，用来核对每张图实际是什么

# 回归自测：加减步长、分类高亮、权重滑杆、偏好跨页、全站报错巡检
python tools/_verify.py
```

## 已知限制

- **没有后端**。购物车和订单存在 `localStorage`，换浏览器就没了。
  登录是假的，验证码固定 `123456`。
- **推荐算法是前端 JS 版**，逻辑与将来的 Java 版一一对应，但没做性能优化。
  菜品数几十道时瞬时完成，真实业务上万条数据需要挪到后端并加缓存。
- **后台的"编辑"和第三方登录**是占位，点了会提示。
- **移动端截图看着像被切掉**是工具问题不是布局问题：
  Chrome 无头模式在 Windows 上有约 500px 的最小窗口宽度，
  传 `--w 414` 实际按 500px 排版再裁图。实测 `scrollWidth == clientWidth`，无横向溢出。

## 下一步

设计确认后，按这个顺序推进：

1. 按 `毕设选题与论文大纲.md` 的第 3 章，把 `recommend.js` 的算法翻成 Java 并写单元测试
2. 建库建表，先把推荐相关的表和偏好表定下来
3. 搭 Spring Boot 骨架 + JWT 鉴权
4. 按页面对应关系实现接口，前端换成 Vue 组件
5. 后厨屏接 WebSocket

**建议先做第 1 步**。先把算法跑通、实验数据出来，再写系统。
反过来的话很容易拖到最后没时间做实验，第 6 章就只能编数据 —— 那是答辩最容易被问穿的地方。
